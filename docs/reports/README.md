# Стандарт отчётов Codex (обязательно после каждого этапа)
Каждый завершённый этап Codex записывает в `docs/reports/YYYY-MM-DD-<topic>.md`:
1. Название PR/Issue, branch, base SHA и HEAD SHA.
2. Что сделано: файлы, функциональные изменения, совместимость.
3. Реально выполненные команды и exit codes (`NOT_RUN` если не было запуска), ссылки на CI и conclusion.
4. Реальное состояние внешних сред: отдельно `NOT_VERIFIED` если нет доступа к Supabase/VPS.
5. Security gates: auth/RLS, лицензии, использование внешнего API, деньги, секреты и пользовательские данные.
6. P0/P1/P2 блокеры с конкретными следующими действиями.
7. Rollback plan; статус `READY_FOR_REVIEW`, `PARTIAL` или `BLOCKED`.

Далее Codex делает **commit и push** отчёта, оставляет ссылку в PR, а замечания — обычными GitHub PR review comments или issue comments. Тогда ChatGPT может прочитать отчёты и дискуссию через GitHub-коннектор без скриншотов.

Никогда не коммитить ключи, пароли, `.env` со служебными секретами, реальные Telegram IDs, private DB, платные raw API ответы, PII, SSH, лицензионные документы. Только обезличенные агрегаты.
Не менять `main` или VPS без отдельного согласования владельцев.
